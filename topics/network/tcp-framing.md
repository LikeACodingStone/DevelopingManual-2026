## 是什么

TCP 提供有序字节流，不保留应用 send 的消息边界。一次 recv 可能获得半条或多条消息，应用必须自行约定长度前缀、分隔符或固定长度。

## 何时使用

自定义二进制协议、音频流或命令通道。本例使用 4 字节网络序长度前缀，并限制单条消息最大长度。

## 如何使用

1. 服务端 bind/listen/accept，客户端 connect。
2. 发送长度头和数据，处理完整发送。
3. 先读满固定头，校验长度上限。
4. 循环读取指定消息长度；提前 EOF 是截断错误。
5. 设置超时并关闭双方连接。

## 常见问题

不要直接发送含指针、填充和主机字节序的 C 结构体。recv 返回 0 表示对方关闭。应在分配缓冲之前检查不可信长度。超时不代表消息边界。

Qt 的 readyRead 只表示有可读数据，readAll 只取当前缓冲，不保证完整业务帧。事件驱动实现应保留跨回调缓冲并循环提取完整帧；教学边界仍见本页的本地示例。结构化载荷可使用 [Protobuf](protobuf.md)，但它不替代传输层分包。
